## Findings and repairs

- **FAIL → PASS: live quantity header was a dead control.** Shared table markup rendered `data-sort` buttons, but only the development preview script handled them. Shared `business.js` now sends allowlisted server sorting, resets pagination, toggles direction and announces applied `aria-sort`. Product browser regressions inspect actual API requests/results and both directions. Initial URL/filter sorting also updates the header after loading.
- **FAIL → PASS: live numeric cells lacked numeric alignment.** Shared browser cell rendering now inherits the shared numeric header class. The product browser regression checks numeric body cells; all live list/report consumers reuse this renderer.
- **FAIL → PASS: movement selection could be restored by a stale response.** A pending availability response survived clearing/researching products or changing mode. Editing an original movement ID also retained the previous original internally. Generation guards now invalidate search/detail/original requests, clear obsolete product/original state, discard stale responses/errors and provide explicit availability loading/error states. Real browser tests hold a completed HTTP response while clearing selection, then release it; the cleared state remains intact. A separately loaded valid reversal is invalidated when its original ID changes, and review cannot open until it is loaded again.
- Corrected stale architecture/decision introductions and inaccurate opening-key/original-lock descriptions. OpenAPI error documentation now names implemented conflict/export/reference errors and missing-record 404s; generator and contract tests were updated together. No API behavior, schema or applied migration changed.
