# API foundation through Stage 12

26 operations are implemented: health, authentication/account, lookups, products, transactions/history, dashboard and reports/CSV. Six user-management/audit operations remain planned behind real authorization/CSRF gates; authorized requests return 404. See OpenAPI per-operation status. Local MariaDB verification passed; MySQL 8.4 and production HTTPS remain pending.

ApiRouter centralizes exact/versioned paths, method allowlists/405 Allow headers and bounded positive integer route parameters. Application registers 26 real operations and six planned business security gates. Health/authentication accept no query fields: unknown, repeated, array-style, control-character and invalid UTF-8/percent-encoded queries return safe 422; size above 4096 bytes returns 414. Health stays `{data:{status:"ok"},meta:{}}`. HEAD omits the body, including errors. Root/subdirectory routing and production preview restrictions are preserved.

Response::success produces data/meta with no-store/nosniff. ExceptionHandler maps trusted HttpException status/code/message/optional field details and headers to one error envelope `{error:{code,message,details?},request_id}`. Unexpected failures return generic 500, and safe private logging omits messages/arguments/bodies. Each request gets a server-generated 32-character lowercase hex X-Request-ID; client IDs are ignored. Errors repeat that identifier in the body; successful clients read the header. No DB errors are automatically exposed as domain conflicts: later services/controllers must map known failures deliberately.

ApiInput provides a bounded raw-body reader and JSON object/field allowlist parser (65536 bytes, depth 32, duplicate keys rejected even through Unicode escapes), strict UTF-8 text and integer/decimal/enum/boolean validation, query allowlists, date validation and ordered maximum 366 inclusive-day ranges. Prices stay strings from 0.00 through 99999999.99. Pagination defaults page 1/per_page 25, bounds page 1–10000/per_page 1–100, and computes bounded offsets. Sorting returns only a trusted server-map expression with ASC/DESC; request strings never become SQL identifiers. Callers must supply role-specific allowlists and perform required-field/domain validation; these utilities do not authorize users or implement business operations.

The shared `public/assets/js/api-client.js` exports window.BizStockApi.ApiClient/ApiError. Escaped APP_BASE_PATH confines same-origin requests and cookies; no-store/redirect rejection apply. JSON/transport failures are normalized. Planned CSV GET handling returns a Blob. Mutations obtain an in-memory token from the real /auth/csrf. Tokens never enter browser storage; concurrent requests share a promise and generation checks reject late stale tokens. 401 clears state/emits bizstock:session-expired; CSRF_INVALID clears tokens. Real login/account screens clear tokens after session changes and handle errors with textContent/focus. Future pages must reuse these behaviors.

The caller creates/retains an Idempotency-Key for each logical product creation/movement and supplies the same key after uncertain-network failure. The client sends it unchanged and never automatically retries mutations, changes keys or simulates completed operations. Actor-scoped replay, canonical fingerprint, original responses and current authorization are documented contracts for Stages 8/9, not implemented here.

OpenAPI includes cookie/CSRF requirements (including login/logout), role/Viewer field visibility, forced password change, inactive/session invalidation, decimal/UTC timestamp types, soft archive, version conflicts, full reversal rules, filtered reports and CSV escaping/formula defense with a 10,000-row/16-MiB export limit. Supporting BIGINT audit identifiers and wide aggregate values use strings to avoid JavaScript precision loss. Production remains MySQL 8.4 with actual verification pending; this stage does not change migrations, database data or credentials.

The .yaml artifact uses JSON syntax, a YAML 1.2 subset, to keep generation/parsing reproducible without adding a YAML runtime dependency. Regenerate with `node bin/build-openapi.cjs`. `node tests/openapi.cjs` validates structure, all local references, operation IDs/status, security and contract guards; it is a focused contract audit, not a complete independent OpenAPI/JSON-Schema validator. Future endpoint stages must update generator, artifact, tests, handlers and client/UI together. Fixtures still perform no network writes or real login.

Checks: composer check covers syntax, loopback HTTP/config and API helper/router contracts. node tests/api-client.cjs covers transport fixtures; node tests/browser/api-live.cjs covers actual health, validation, CSRF bootstrap and anonymous refusals. composer test:auth verifies real database/session/security and browser login/account flows against disposable local MariaDB. MySQL execution remains pending. Browser dependencies stay under tests/browser; no frontend build is introduced.

Stage 12 current behavior: real transaction/product/dashboard/report routes and restricted serializers now implement these contracts. Report CSV uses the explicit format=csv query, safe fixed filenames, X-Snapshot-At and all matching pages within 10,000 rows/16 MiB. CSV errors stay JSON. Transaction report includes UTC snapshot_at and exact gross captured-price reference_value. Product low_stock=true includes zero; status=low_stock is positive-low only. Stage 13 user/audit contracts remain planned. The complete-flow browser test validates actual response objects against the documented schema subset as well as permissions and effects; this is not a claim of an independent full OpenAPI validator or MySQL execution.

## Stage 13 final contract status

All 32 OpenAPI operations are now implemented, including Admin-only GET/POST users, PATCH/DELETE users/{id}, POST users/{id}/reset-password and GET audit-events. Account writes enforce CSRF; validation, duplicate username and LAST_ADMIN conflicts are real typed errors. Reset responses omit secrets and require forced change; session_version invalidates previous sessions. Audit filtering/pagination/sorting uses shared bounds and positive fields. No planned feature returns simulated success. MySQL 8.4 and production HTTPS verification remain pending.
