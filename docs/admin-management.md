# Admin accounts, resets and audit

Stage 13 implements all six formerly planned operations: GET/POST users, PATCH/DELETE users/{id}, POST users/{id}/password-reset and GET audit-events. Admin only, current session required; all writes require CSRF. No public signup. `/users` and `/audit-events` share the live shell, components, client, pagination, search, errors and dialogs.

Create uses a unique trimmed lowercase ASCII username, bounded full name, exact role and existing 12–72 UTF-8 byte password policy. Passwords are hash-only, never returned or audited. Owner enters a temporary secret and manually delivers it privately; no email is sent. Creation/reset requires next-login password change. Every edit/reset/deactivation increments session_version and revokes earlier sessions, including self-edits; log in again when editing your own account. Reactivation retains the account and history.

UserService acquires security_locks row 1 before actor/target user locks, using AtomicWrite's optional security lock and bounded retries. It rechecks active Admin/session/forced flags under lock. Deactivating/demoting the final active Admin returns 409 LAST_ADMIN. All domain changes and safe audit values commit together. Password-change and stock services retain their existing lock/transaction behavior. No migration changed.

The audit log is append-only, Admin-only, with bounded sorting/pagination and entity/actor/Manila date filters. Details show safe before/after, request ID and UTC stored timestamps displayed in Manila. Historic actors and products are retained. Password/hash/session tokens never appear. Audit insertion failure rolls back account writes.

Emergency recovery is a trusted operator CLI, not an HTTP bypass or initial bootstrap. Recover an **existing** account by ID; it becomes active Admin with a new hash, forced change and revoked sessions. A reason and safe `admin.emergency_recovery` event commit together under the sentinel lock. Use `bin/recover-admin.ps1 -UserId ID -Reason 'Operator recovery reason'` for hidden double password entry, or `php bin/recover-admin.php ID 'Reason' --password-stdin` through a private stdin channel. Never put passwords in arguments/history; restrict CLI/database/secret-file access. Do not use installed development accounts for tests.
